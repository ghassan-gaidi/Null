# Null Website Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task (this plan was written for inline execution: one cohesive HTML/CSS page, tasks share one stylesheet/copy source). Steps use checkbox (`- [ ]`) syntax for tracking, ticked as evidence lands.

**Goal:** Ship the approved "Redacted / full-dossier" landing page for Null on GitHub Pages with zero JS and zero third-party requests.

**Architecture:** A static `site/` directory deployed as-is by a GitHub Pages Actions workflow. One `index.html` + one hand-written `style.css` + two self-hosted woff2 fonts. No build step, no JS; all copy traced to repo sources and stamped in the footer.

**Tech stack:** HTML5, hand-written CSS (custom properties), woff2 fonts (Anton, JetBrains Mono, OFL), GitHub Actions (`configure-pages`/`upload-pages-artifact`/`deploy-pages`).

**Spec:** `docs/superpowers/specs/2026-10-25-website-design.md` (the authoritative visual system, section map, budgets, and verification plan).

## Global Constraints

- **0 bytes of JavaScript.** No `<script>` in shipped HTML; interactions are anchors + CSS only.
- **0 third-party requests.** No CDN fonts, no analytics, no external images; fonts are `site/fonts/*.woff2` referenced with **relative URLs only** (Pages serves under `/null/`).
- Copy is sourced, never invented: every number equals the value in `README.md`/`docs/security-posture.md`/`docs/threat-model.md`/`SUMMARY.md` (`cargo xtask doccheck` does not guard `site/` — §7.6 of the spec is the guard).
- Design tokens verbatim: paper `#ebe7de`, ink `#141414`, yellow `#f2c744`, red `#d0342c` (large/bold only), red-alt `#8f2c25` (small red text), ink-dim `#55524a`, band `#e2dccd`, ok-green `#1d7a2d`.
- Zero animation; `:hover` and `:focus-visible` only.
- Budgets: HTML ≤ 60 KB, CSS ≤ 15 KB, fonts ≤ 75 KB; contrast ≥ 4.5:1 for body copy ( Yellow/ink and paper/ink pass; red only at display sizes).
- Redaction bars/stamps are decorative and `aria-hidden` or text-adjacent; no load-bearing text hidden behind bars.
- License: page content under repo license (MIT OR Apache-2.0); fonts under OFL, `site/fonts/OFL.txt` carries the notices.
- Every task: verify in a served browser before committing; commits are small and per-task on `main` (repo convention).

## Review Focus

Copy integrity and asset hygiene are the two failure modes no automated gate covers. Five, most likely first, each pinned to its owning task's steps:

1. **Absolute asset URLs breaking under the `/null/` base path** — expect every `href`/`src` to be `#…`, `fonts/…`, `style.css`, or an absolute `https://github.com/ghassan-gaidi/null/…` link. Pinned in Task 8 (grep assertion in link audit).
2. **Numbers on the page drifting from the repo** — expect `≤ 50`, `7 days`, `2048`, `5/5`, `124`, triple ratchet wording to match sources byte-for-byte. Pinned in Task 8 (copy audit table).
3. **Third-party request leak** — expect network panel to show only local `index.html`/`style.css`/fonts; grep forbids `fonts.googleapis|gtag|analytics|cdn.` in shipped files. Pinned in Task 8.
4. **Load-bearing copy hidden by redaction bars** — expect bars to sit where plain replacement text is adjacent and `aria-hidden`; nothing readable is covered. Pinned at build time in Tasks 1–2 (hero bars carry their info in remaining text), re-checked by browser pass in Task 8.
5. **Small red text failing contrast on paper** — expect `#d0342c` only at ≥17px/bold/stamp sizes; smaller red text uses `#8f2c25`. Pinned in Task 4 (SOTA `.dud` marks) and Task 5 (NOT RUN pills use white-on-red, not red-on-paper).
